# compact-header

Small Vite-based workspace for iterating on a compact header implementation currently wired to the archived intranet snapshot in `DET intranet.html`.

The workspace now supports a maintained nester header source for Squiz-compatible markup while keeping a static local preview page for development.

## Requirements

- Node.js 18+ recommended
- npm

## Setup

Install dependencies:

```bash
npm install
```

## Development

Start the local dev server:

```bash
npm run dev
```

Current behavior:

- Vite opens `DET intranet.html`
- legacy page assets remain under `DET intranet_files/`
- maintained header source lives under `src/nester/`
- local dev preview uses static text in `DET intranet.html`
- build copies tokenized Squiz header markup into `dist/header.html`

## Commands

```bash
npm run dev
npm run build
npm run preview
```

Command reference:

- `npm run dev`: starts Vite with host binding and opens the current HTML entry page
- `npm run build`: builds `DET intranet.html` with Vite, then copies `src/nester/header.html` to `dist/header.html` unchanged
- `npm run preview`: serves the production build locally

## Project Structure

```text
.
|- DET intranet.html
|- DET intranet_files/
|- scripts/
|  \- copy-squiz-header.mjs
|- src/
|  |- css/
|  |- js/
|  \- nester/
|     |- header.css
|     |- header.html
|     \- header.js
|- package.json
|- vite.config.js
\- prompts.md
```

Notes:

- `src/css/` is the intended home for maintained styles
- `src/js/` is the intended home for maintained JavaScript
- `src/nester/header.html` is the tokenized Squiz-compatible header source of truth
- `src/nester/header.css` and `src/nester/header.js` contain maintained utility-row and header-specific presentation/behavior
- the utility row is full-width, while its contents are constrained to a `1232px` maximum width on desktop
- `DET intranet.html` and `DET intranet_files/` are ignored by Git to keep the repository focused on source changes

## Header Workflow

- Edit `src/nester/header.html` when changing the tokenized header markup intended for Squiz import.
- Edit `src/nester/header.css` and `src/nester/header.js` for maintained header-specific styling and behavior.
- Use `DET intranet.html` for local preview behavior and static text rendering.
- `dist/header.html` is generated by the build script and preserves Squiz placeholders such as `%globals_site_url%`.

Current header split:

- Quick links row: full-width background bar with constrained inner content
- Main header/nav row: compact Figma-inspired structure below quick links
- Local preview: static URLs/text for browser rendering
- Dist artifact: tokenized Squiz markup copied unchanged from `src/nester/header.html`

## Workflow Conventions

- Prefer making new changes in `src/` instead of editing copied legacy assets unless migration work specifically requires it
- Keep changes small and verify behavior through the Vite dev server before committing
- Update this README when scripts, entry points, or folder conventions change

## Troubleshooting

Dev server opens the wrong page:

- check the `dev` script in `package.json`
- confirm the entry path still matches `DET intranet.html`

Build output does not reflect source changes:

- confirm your change was made in the file actually loaded by the page
- header layout/style changes should usually be made in `src/nester/`
- local preview changes may also require checking `DET intranet.html`

`dist/header.html` is missing or does not contain Squiz tokens:

- run `npm run build`
- confirm `scripts/copy-squiz-header.mjs` exists and `package.json` still runs it after `vite build`
- confirm the tokenized source remains in `src/nester/header.html`

`npm run dev` fails after checkout:

- run `npm install`
- confirm your Node.js version is compatible with the installed Vite version
